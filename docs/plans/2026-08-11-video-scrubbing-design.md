# 800×800 插帧视频滑动设计

## 目标

把现有 31 张人像关键帧转换成一条接近连续变化的视频，并让网页滑杆直接控制视频画面。最终交付分辨率统一为 800×800，全程使用免费、可在本地重复运行的工具。

## 技术选择

主方案采用 RIFE 进行神经网络插帧。它支持任意时间点插帧，运行速度适合批量处理 30 组相邻图片。若眼镜、下颌或帝冕珠帘出现无法接受的重影，再用 FILM 单独重算问题区间。

FFmpeg 负责缩放、编号整理和 WebM、MP4 编码。单独使用 FFmpeg 运动插值容易在五官与珠帘附近产生拉丝，仅保留为故障排查手段。

## 数据流程

1. 从 `public/frames/frame-00.png` 到 `frame-30.png` 读取 31 张关键帧。
2. 统一缩放并裁切为 800×800，保持人脸居中。
3. 每组相邻关键帧补 7 张中间帧，最终得到 241 帧。
4. 先输出「小难梁→牢梁」和「梁神→梁祖」两段原型，检查身份稳定性与复杂饰物。
5. 原型通过后处理完整序列，编码 WebM 与 MP4。
6. 网页把滑杆归一化位置映射到视频 `currentTime`，再把当前视频帧绘制到现有 Canvas。

## 网页行为

保留当前界面、六个状态标签和 0—30 的语义读数。拖动时允许连续位置输入，文字状态仍按六个里程碑更新。Canvas 固定以 800×800 视频为源，页面展示尺寸继续由现有响应式 CSS 控制。

视频需要短关键帧间隔，以减少拖动时的解码等待。优先加载 WebM，MP4 作为浏览器兼容回退。

## 错误处理

- 视频尚未载入时禁用滑杆并显示载入进度。
- 当前浏览器无法加载 WebM 时自动尝试 MP4。
- 视频定位失败时保留最后一帧，并给出刷新提示。
- 插帧脚本缺少模型或 FFmpeg 时输出明确的中文错误信息。

## 验收标准

- 输出视频为 800×800。
- 31 张原图都准确出现在对应里程碑位置。
- 桌面与手机拖动时没有明显跳帧或长时间白屏。
- 人脸身份保持稳定，眼镜、下颌和帝冕珠帘没有大面积重影或融化。
- 单元测试、浏览器交互测试和 GitHub Pages 构建通过。
