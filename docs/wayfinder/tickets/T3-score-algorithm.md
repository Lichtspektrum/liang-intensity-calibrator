# T3: 打分算法精确公式

**类型**: grilling（HITL）
**状态**: open
**阻塞**: T7（D1 schema）, T9（冷启动切换条件）, T11（API 契约）

## Question

确定梁氏浓度分值的精确数学模型。已确定的约束：

- 分值范围 0-100，初始值 50（对应梁子/梁圣边界附近）。
- **投票是主要驱动**（Q16）：用户每日 Up/Down 投票决定分值。
- **贝叶斯平均**（Q7=D）：先验均值 50，小样本时偏保守。
- **月半衰期衰减**（Q8=一个月）：旧票权重按月向 50 衰减。
- **新闻仅冷启动**（Q16）：投票量足够后新闻不直接加减分。
- Up/Down 是方向性投票（Q18=A）：Up 推高分值，Down 拉低分值。
- 分值需要平滑变化，不能在每天投票截止时跳变。

### 需要决策的细节

1. **贝叶斯平均公式**：
   - 先验强度：多少票之后分值才开始明显偏离 50？（比如先验权重等效 100 票？）
   - Up/Down 投票如何映射为贝叶斯参数？（威尔逊区间？拉普拉斯平滑？简单加权平均？）
2. **时间衰减的实现方式**：
   - 方案A：每张票有自己的"权重半衰期"——投票时权重为 1，一个月后权重为 0.5，两个月后 0.25……最终趋近 0，分值趋向先验。
   - 方案B：日聚合衰减——每天汇总当天的 Up/Down 数，对每天的聚合值应用衰减。
   - 方案C：指数移动平均（EMA）——每天结束时 score = score * e^(-λ) + today_votes * (1-e^(-λ))，λ 使得 30 天后权重减半。
3. **衰减目标**：衰减是让所有票的权重都趋向 0（分值趋向 50），还是旧票权重不变但新票持续覆盖？
4. **分值到 UI level 的映射**：0-100 如何映射到现有 level 0-30？线性？非线性（两端需要更极端的事件才能到达）？
5. **每日投票重置时机**：按用户本地时区？按 UTC 0 点？按北京时间 0 点？

### 推荐方向

EMA 方案（方案C）最简单，D1 只需存当前 score 和每日聚合，不需要存每张票的时间戳。月半衰期 λ = ln(2)/30 ≈ 0.023 per day。贝叶斯可以揉进 EMA 的更新公式里。
