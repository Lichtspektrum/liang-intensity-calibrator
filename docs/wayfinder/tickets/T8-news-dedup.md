# T8: 新闻聚类去重规则设计

**类型**: grilling（HITL）
**状态**: open
**依赖**: T1（新闻源可访问性调研）
**阻塞**: T11（API 契约）

## Question

每小时 Cron 采集各源新闻时，同一事件可能在多个源、多个时间点被重复采集。需要确定聚类/去重规则。已确定的约束：

- 同日同类新闻合并为同一事件（Q12=A）
- 不同来源同类新闻要合并
- 社区讨论热度适当加权（Q12）

### 需要决策的

1. **聚类维度**：什么算"同一事件"？
   - 按关键词重叠度？（标题/摘要中相同实体词+时间窗口）
   - 按 URL 去重（最简单，但同一事件不同链接会漏掉）
   - AI 判断是否同一事件？（最准但每小时跑 AI 聚类成本高）
2. **合并窗口**：同日合并（自然日）？还是 24 小时滑动窗口？
3. **多源合并后的影响**：
   - 极性：取平均？加权平均（官方源权重高，社交媒体权重低）？
   - 影响力：多源报道的事件影响力更高（这是"社区热度加权"的一种形式）？
   - 摘要：AI 重新生成合并后的摘要？
4. **社区热度指标**：从 T1 调研结果中选择可用的热度指标（阅读量、讨论数、播放量等），如何映射到影响力加权系数？
5. **旧闻过滤**：如何避免重复处理已经分析过的新闻？（已处理 URL/内容 hash 记录在 KV？）
