# [Wayfinder] 社区投票梁氏浓度 + 自动新闻时间线

## Destination

为滑动变祖器增加后端能力：网友每日 Up/Down 投票驱动梁氏浓度分值（0-100，映射到现有 level 0-30），初始值 50，投票权重按月半衰期衰减回归 50；自动采集中文科技圈+官方渠道新闻，经 Workers AI 分析后用于冷启动打分和时间线事件标记。现有 UI 保持不变，仅在左侧加入投票面板（Up/Down + 比例条）、右侧加入纵向时间线（关键事件节点，可回看历史分值）。

## Notes

- **技术栈**：Cloudflare 全家桶——Workers（扩展现有 worker.ts）、D1（投票/事件存储）、KV（限流/缓存）、Cron Triggers（每小时新闻采集）、Workers AI（中文情感分析+事件摘要）。不引入外部 API key。
- **领域语言**：
  - **Voter**：由 fingerprintjs 浏览器指纹标识，同 IP 每天最多 5 票（宽松频率限制，防简单刷票）。
  - **Vote**：每天每人一票，方向 Up 或 Down，当天内可改投。
  - **Score**：梁氏浓度 0-100（映射到现有 level 0-30），由贝叶斯平均投票产生，先验均值 50，按月半衰期向 50 衰减。
  - **NewsEvent**：每小时 Cron 采集的新闻，AI 输出极性（-1~+1）+ 影响力（0~1）+ 摘要；同日同类新闻合并为一个事件，社区讨论热度加权。
  - **TimelineMarker**：时间线上的节点，含日期、当时分值、关联事件。从上线第一天开始积累，不回溯历史。
  - **ColdStart**：上线初期投票不足时由新闻情感驱动初始分偏移；投票量足够后投票成为唯一分值驱动，新闻仅用于时间线标记。
- **滑杆行为**：用户可自由拖动浏览各形态，松手后自动回弹到社区共识分值。滑杆拖动本身不触发投票。
- **实时性**：页面加载取一次分值，不做 WebSocket 实时推送，用户刷新获取最新值。
- **v1 范围**：投票系统 + 自动新闻采集 + 时间线全部 v1 上线。
- **关联**：本 map 是 issue #2（功能建议）的设计分解。
